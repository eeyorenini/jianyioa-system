## 一、这次修的是什么 bug

**现象**：小程序首页「待办事项」里点任意一条，不跳转，提示页面不存在 / 无关联页面。H5 端正常。

**根因（一句话）**：后端 `/api/todo/center` 返回的 `url` 字段仍是分包改造前的 `/pages/xxx`，而这些页面在 10-22 凌晨已经迁进分包，真实路径变成 `/pkg-xxx/xxx`，跳转必然 404。

后端返回的 11 处旧路径（全部在 `server.js` 的 `/api/todo/center` 里）：

| 待办类型                  | 后端返回（旧）                     | 小程序实际路径                           |
| --------------------- | --------------------------- | --------------------------------- |
| 采购待审核 / 报销待确认 / 待上传回执 | `/pages/purchase/detail`    | `/pkg-purchase/purchase/detail`   |
| 通用审批                  | `/pages/approval/detail`    | `/pkg-misc/approval/detail`       |
| 派工待审核 / 我的派工          | `/pages/dispatch/detail`    | `/pkg-inspect/dispatch/detail`    |
| 合同待审核 / 增减项待审核        | `/pages/contracts/approval` | `/pkg-finance/contracts/approval` |
| 节点即将到期 / 逾期预警         | `/pages/projects/detail`    | `/pkg-project/projects/detail`    |
| 待整改巡检                 | `/pages/inspection/detail`  | `/pkg-inspect/inspection/detail`  |

**为什么 H5 正常**：H5 没拆分包，`/pages/xxx` 就是它的真实路径。

### 修法（分三层，缺一不可）

| 层       | 做法                                                                                       | 为什么                                          |
| ------- | ---------------------------------------------------------------------------------------- | -------------------------------------------- |
| **后端**  | **不改**，继续返回 `/pages/xxx`                                                                 | 后端是三端共用的，绑定小程序路径会让 H5 全挂（第一版改成了 `/pkg-`，已回退） |
| **运行期** | `utils/pageUrl.ts` 的 `resolvePageUrl()`：小程序把 `/pages/xxx` 映射成 `/pkg-xxx/xxx`，H5/App 原样返回 | 后端返回的 url 是运行期字符串，不进构建流程                     |
| **构建期** | `vite.config.ts` 的 `subpackagePaths()` 插件：小程序构建时把源码里的 `/pages/xxx` 字面量自动改写               | 让业务代码两端可以写同一份路径                              |

调用点：`pages/home/index.vue` 的 `goTodoUrl`、`pkg-misc/todo/index.vue` 的 `openItem`（H5 端对应 `pages/home/index.vue`、`pages/todo/index.vue`）。

## 二、代码统一：现在是什么状态

### 统一的规则

> **所有页面跳转路径在源码里统一写 `/pages/xxx`，永远不写 `/pkg-xxx/xxx`。**

- 小程序构建时由 vite 插件自动改写（映射表 `src/utils/pageMap.ts`）
- 后端接口返回的 url 由 `resolvePageUrl()` 在运行期映射
- H5 / App 什么都不用做，`/pages/xxx` 本来就是对的

**新增页面时**：

1. 源码里跳转写 `/pages/新目录/页面`
2. 要进分包 → 改 `pages.json` 的 `subPackages` + `pageMap.ts` 的 `PAGE_DIR_TO_PKG`
3. 两端源码保持同一份写法，不用再考虑平台差异

### 本次统一的实际改动

- 小程序端 **121 处** `/pkg-xxx/xxx` 全部回退成 `/pages/xxx`（涉及 32 个文件）
- H5 端补齐 **14 个文件**漏掉的 `absAsset()`（这是 App 端必需的，见下）
- 两端 `utils/pageMap.ts`、`utils/pageUrl.ts`、`utils/upload.ts` 完全一致
- 两端 `home/index.vue` 的 `handleQuick` / `goTodo` / `goTodoUrl` **逐行一致**
- 两端 `todo/index.vue` 的 `openItem` 逐行一致

### 对照结果

100 个同名文件里，**79 个完全一致**（仅差 `navStyle`），21 个仍有差异 —— 全部属于下表三类平台必需项。

## 三、为导出 App 做的准备（重要）

导出 App 时用的是 **H5 那份源码**（`jianyioa-app/mobile`，mobile 分支），不是小程序那份。

App 端和 H5 的区别：**App 没有同源，`/uploads/x.jpg` 这种相对路径加载不出来**，必须绝对地址。而 `absAsset()` 的条件编译正好覆盖 `APP-PLUS`：

```ts
// utils/api.ts
// #ifdef APP-PLUS
origin = 'https://erp.fujinwanjia.com';
// #endif

export function absAsset(path) {
  if (isAbsolute(path)) return path;      // http / blob / wxfile / data 原样
  if (path.startsWith('/')) return API_ORIGIN + path;   // H5: 原样；App: 补域名
  return API_ORIGIN ? API_ORIGIN + '/' + path : path;
}
```

**所以本次统一 H5 端 `absAsset` 不是为了代码好看，是导出 App 的前置条件。** 如果 H5 端继续用自己那套「什么也不做」的等价函数，打包成 App 后所有合同照片、施工日志照片、报销票据会全部裂开。

同类必须注意的还有两处，已经在本次统一里处理：

- `projects/detail.vue` 的 `openOneAttachment` 原来写 `location.origin + url` —— **App 端没有 `location`，会直接抛错**，已改成 `absAsset(url)`
- `projects/log-add.vue` 的 `previewImg` 原来是一段恒等函数，已改成 `photos.map(p => absAsset(p.url || p))`
