## 1. 改动强制流程（双端一致性）

任何涉及**移动端页面**或**业务逻辑**的修改，必须按以下顺序执行，**不得跳步、不得只改一端**。

### 1.1 顺序
1. **先改 H5**：在 `jianyioa-app/mobile/src/`（分支 `mobile`）修改源码。
2. **再改小程序**：把同一处改动落到 `/Users/gtamer/Desktop/jianyioa-mpweixin/mobile/src/`（分支 `mp-weixin`）。
3. **核验一致**：对每个改动文件执行
   ```bash
   diff -u <H5路径> <小程序路径>
   ```
   - 预期只应剩下**小程序专属差异**（见 1.2）。
   - 若出现业务逻辑差异 → 说明漏改或改错，必须补齐。
   - ⚠️ **不要用 `git diff mobile mp-weixin` 看工作区改动**：worktree 里是未提交内容，git diff 比的是提交，会显示为空。
4. **构建 + 部署**：
   - H5：`cd jianyioa-app/mobile && npm run build:h5` → `cp -R dist/build/h5/. ../../server/public-mobile-h5/`
   - 小程序：`cd /Users/gtamer/Desktop/jianyioa-mpweixin/mobile && npm run build:mp-weixin` → 把 `dist/build/mp-weixin/.` 复制到 `/Users/gtamer/Desktop/jianyioa-miniprogram/`（**平铺到根**）。
   - 两端都要构建，**不能只改源码不重构建**——用户是在小程序里看效果提需求的。

### 1.2 两分支已知合法差异（同步时不要盲目整文件覆盖）
- `navbar.ts`、`absAsset`、状态栏/胶囊避让相关逻辑：小程序专属。
- `src/pages.json`：小程序 tabBar 图标用 `png`，H5 用 `svg`；tabBar 均为 5 项（首页/项目/巡检/采购/我的），**微信硬上限 5 项，不可加第 6 项**。
- `project.config.json` 仅小程序侧存在。
- 版本号单一来源是 `mobile/package.json` 的 `version`，经 `vite.config.ts` 的 `define: { __APP_VERSION__ }` 注入；改版本只改 package.json，两分支都要改。
- 可用特征字符串快速自检构建产物：`toDate(`、`index: 4`、`_key`、`v{{ APP_VERSION }}`。

## 2. 发版规范

### 2.1 版本号
- **不要凭 package.json 或 git tag 推断"用户认为的当前版本"**：代码基线常常领先或落后于线上实际版本。
- **发版前必须问用户「现在版本是多少 / 这版叫什么」**，或明确说明依据（如"代码里是 2.3.7"）后再定版本号。
- 五处 `package.json` 必须统一：根目录、`server/`、`web/`、`jianyioa-app/mobile/`、`jianyioa-mpweixin/mobile/`。

### 2.2 标签命名
三个仓共用同一个远程（`github.com:eeyorenini/jianyioa-system.git`），tag 是全局命名空间，**不能重名**：
- `v{版本号}` → 主仓 main（如 `v2.4.1`）
- `v{版本号}-mobile` → 移动端子仓 mobile（如 `v2.4.1-mobile`）
- `v{版本号}-mpweixin` → 小程序 mp-weixin（如 `v2.4.1-mpweixin`）

### 2.3 升级包目录结构
输出根目录：`/Users/gtamer/Desktop/jianyioa项目版本管理/版本升级/v{版本号}/`，**文件夹名 = 版本号**。用户**直接覆盖**即可：

```
v{版本号}/
  server/server.js            → D:\wwwroot\jianyioa\server\server.js
  server/public-mobile-h5/    → D:\wwwroot\jianyioa\server\public-mobile-h5\   （移动端 H5）
  web/dist/                   → D:\wwwroot\jianyioa\web\dist\                  （PC 前端）
  miniprogram/                → 微信开发者工具导入上传，不走服务器
  修改记录.md
```

### 2.4 构建规范
**生成前必须先重新 build，不能直接拷旧产物**：
1. `cd web && npm run build`（PC）
2. `cd jianyioa-app/mobile && npm run build:h5` → `cp -R dist/build/h5/. ../../server/public-mobile-h5/`
3. `cd /Users/gtamer/Desktop/jianyioa-mpweixin/mobile && npm run build:mp-weixin` → 同步到 `/Users/gtamer/Desktop/jianyioa-miniprogram/`
4. 拷 `server/server.js`、`server/public-mobile-h5/`、`web/dist/`、`jianyioa-miniprogram/` 进版本目录

### 2.5 safe-delete 拦截处理
构建时若遇到 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`：
- 先 `mv dist /tmp/web-dist-bak-$(date +%s)`（PC）或 `mv dist/build/h5 /tmp/h5-bak-$(date +%s)`（H5）
- 再重新构建。构建偶发被拦截，重跑一次即可。

### 2.6 修改记录模板
`修改记录.md` 固定章节：
1. 修改时间
2. 修改内容（分点说明，带根因分析）
3. 涉及文件（表格：部署路径 ↔ 来源）
4. 部署步骤（含 pm2 命令）
5. 上线前检查项（勾选列表）
6. 注意事项
7. Git（commit + tag）

## 3. 本机运行红线

### 3.1 后端启动
- 启动命令：`cd server && node server.js`
- 监听端口：**3002**（API + PC 前端 + 移动端 H5 `/m/`）
- **改 `server/server.js` 必须重启后端才生效**（无热重载）
- 重启方式：取 PID → kill → 重新启动
  ```bash
  PID=$(lsof -tiTCP:3002 -sTCP:LISTEN); kill $PID; cd server && node server.js
  ```
- ⚠️ **不要用 `nohup ... &`**：本环境沙箱会在命令结束后回收该进程。用 Bash 工具的 `run_in_background: true` 启动。
- node 路径用 `/Users/gtamer/.workbuddy/binaries/node/versions/22.22.2-6/bin/node`（与本机既有进程一致）
- 启动约 10~12 秒后监听（要先加载 .env、连远程 MySQL、require puppeteer）

### 3.2 代理
- 本机有代理：`curl` 自测要加 `--noproxy '*'`，否则返回 502。

### 3.3 前端 dev server
- 本机唯一入口是 **3002**。5555/5173/3000 均无监听。
- 若用户说"本地看不到效果"，先确认他访问的是 `http://127.0.0.1:3002` 或 `http://localhost:3002`，不是 dev server 端口。

### 3.4 pm2 在本机不可用
- `pm2 start` 在本机沙箱会被 SIGTERM（exit 137），app 列表为空。长时间自测仍用 `node server.js` 后台任务。

## 4. 编码红线

### 4.1 TypeScript 语法禁区
- **`.vue` 里的 `<script setup>` 没写 `lang="ts"` 时，禁止出现任何 TS 语法**（类型标注、`as any`、泛型），否则构建报 `Unexpected token, expected ","`。
- 只有 `.ts` 文件能写类型。

### 4.2 移动端 UI 限制
- `uni.showModal` 的 `confirmText` **不得超过 4 个汉字**（微信审核要求），超长会被驳回。
- 小程序 tabBar **硬上限 5 项**，不可加第 6 项。

### 4.3 时区处理
- 数据库连接 `dateStrings: true`，所有时间用 `new Date().toISOString()` 写入 → **库里是 UTC 字符串**。
- 前端显示要按 UTC 解析再转本地（`"YYYY-MM-DD HH:mm:ss"` → 补 `Z`），否则少 8 小时。
- 统计「今日」的起点用本地零点的 UTC 表示：`new Date(y,m,d,0,0,0).toISOString()`。

### 4.4 请求头与传参
- `x-user-role` 请求头**不能放中文**。`web/src/main.js` 拦截器写 `user.role_code || user.role_name`，退到中文（如「超级管理员」）时浏览器直接抛错，请求发不出去、全站接口静默失败。
- H5 的 `<img>` / `<iframe>` / `window.open` **无法携带自定义请求头** → 预览类 URL 必须拼 `?user_id=`。

### 4.5 密钥与配置存储
- 小程序 appid/secret **存在数据库** `system_settings` 的 `wechat_mini`（`{setting_value:{app_id,app_secret}}`），**不要写 `.env`**——`server/.env` 已被 git 跟踪。
- `getMiniConfig()` 优先读 `WX_MINI_APPID/WX_MINI_SECRET` 环境变量，再回退数据库。

### 4.6 SPA 路由兜底
- PC 端 SPA fallback 不能用 `startsWith('/m')`：会把 `/message-center`、`/main-materials`、`/material-orders` 当移动端。
- 必须 `=== '/m' || startsWith('/m/')`。

## 5. 权限模型口径

### 5.1 员工 id 与客户 id 撞号
- `employees.id` 和 `customers.id` 是**两套独立自增序列，会撞号**（实测 emp#6↔客户#6、#11↔#11 等）。
- `x-user-id` / `query.user_id` 传的是**员工 id**，绝不能用 `SELECT phone FROM customers WHERE id = x-user-id` 判「是不是客户」。

### 5.2 借权（身份借用）
- PC + 移动端均支持。localStorage key：`impersonator` / `impersonating`。
- 借权后权限完全按目标员工，admin 特权一并失去。
- 入口在个人中心 hero「🔓 借用权限」（仅 `isAdmin && !impersonating`）。

### 5.3 微信登录（小程序）
- 身份链路：`wx.login` 静默拿 code → 后端 `jscode2session` → openid → **手机号（唯一认证标识）**绑定到 `customers`。openid 只用来"记住这台微信"，不是认证。
- ⚠️ **头像昵称拿不到**：`wx.getUserProfile` 2022-10-25 已回收。只能用 `<button open-type="chooseAvatar">` + `<input type="nickname">` 让用户主动填写，且**不能当身份标识**。

### 5.4 启动流程与登录守卫
- 首屏是 **`pages/landing/index`**（免登录落地页），`pages/login/login` 已降为普通页。**不要把登录页改回 pages[0]**，否则微信审核会以「未体验即要求授权登录」驳回。
- 免登录白名单在 `stores/user.ts` 的 `PUBLIC_PAGES`，当前 5 项：
  `pages/landing/index`（引导页）、`pages/showcase/index`（样板工地）、`pages/login/login`、`pages/bind/index`、`pages/bind/scan`（员工扫码绑定）。
  `checkAuth()` 只在**非**白名单页跳登录。**新增游客可访问的页面必须加进这个数组**，否则冷启动直达会被 reLaunch 到登录页。
  - ⚠️ `pages/bind/scan` 进页面时**还没有身份**（绑定成功后才写 storage），漏加必被守卫踢走，绑定码白扫。
- `pages/showcase/index`（样板工地）是**纯静态演示页**：所有数据写死在前端，不请求任何接口，用途是满足微信「先体验后授权」——游客能翻完一套样板工地，点模块时才弹登录。
  - ⚠️ 该页**不要接真实接口**。接了就变成泄露客户工地数据（`backup-20261020/uploads_trash_orphans` 里的实拍图属于客户隐私，也不能拿来当素材）。
  - 页面上的「示例演示」角标和底部说明文字是**审核用的免责声明**，别删。
- 冷启动时 `getCurrentPages()` 为空，`currentRoute()` 会回退 `getEnterOptionsSync().path`——改这段别把回退删了。
- 需要身份的入口用 `utils/permission.ts` 的 `requireLogin()`：弹 `showModal`（去登录 / 再逛逛），**不能静默跳转**。当前调用点：`pages/showcase/index` 的模块九宫格与施工记录。

### 5.5 引导页素材（`src/static/landing/`）
- 7 张 JPEG，共约 75KB：`hero-bg`、`feat-progress`、`feat-inspect`、`feat-material`、`case-living`、`case-plumbing`、`case-tiling`。
- 全部由 SVG 手绘 + Chrome headless 截图生成（脚本思路见下），**不是 AI 生图、也不是实拍**，无版权风险。
- 小程序主包限制 2MB，当前包体约 1.04MB。**再加图前先量包体**：
  ```bash
  python3 -c "import os;print('%.2f MB'%(sum(os.path.getsize(os.path.join(r,f)) for r,d,fs in os.walk('dist/build/mp-weixin') for f in fs)/1024/1024))"
  ```
  注意 `du -sh` 显示的是磁盘块占用（约 1.9M），**比真实大小大一倍**，别被吓到。
- 生成工具：`server/node_modules/puppeteer` + 系统 Chrome
  （`executablePath: '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'`，
  puppeteer 自带的 chromium 在本机沙箱起不来）。

## 6. 沟通约定

### 6.1 bug 报告格式
用户报 bug 时，按以下顺序追问：
1. **哪个端？**（PC / H5 / 小程序）
2. **哪个账号？**（员工 id 或姓名）
3. **哪个页面？**（URL 或页面名称）
4. **复现步骤**（点了什么、输入了什么）
5. **期望 vs 实际**

### 6.2 "看不到效果"排查清单
1. 确认访问的是 **3002** 端口（不是 5173/5555/3000）
2. 确认后端在跑：`lsof -tiTCP:3002`
3. 确认不是浏览器缓存：Cmd+Shift+R 硬刷新
4. 确认不是线上域名：检查地址栏是 `127.0.0.1:3002` 还是 `erp.fujinwanjia.com`
5. 确认产物已构建：`ls web/dist/assets/` 看 chunk 时间戳

### 6.3 数据一致性口径
- 本机与线上**连的是同一个远程库**（`DB_HOST=116.204.19.53`），数据完全一致。
- 若同一账号两端看到不同内容 → **不是数据库问题**，是代码版本不同（一端已更新、一端还是旧版）。

## 附录 B：发版升级目录结构红线（2026-10-28 追加）

> 本附录是为防止再次出现「生产升级包」嵌套目录、zip 中文乱码、版本号不一致等错误而追加的强制规范。

### B.1 目录结构：v{版本号}/ 根下直接放标准子目录

输出根目录固定为 `/Users/gtamer/Desktop/jianyioa项目版本管理/版本升级/v{版本号}/`。

**用户的实际操作习惯是：打开 v{版本号}/ 文件夹，把里面的 server/、web/、miniprogram/ 等子目录直接复制到服务器对应位置。**

因此，**标准子目录必须直接位于 v{版本号}/ 根下，绝不允许再套一层中间目录**。

正确结构：

```
v{版本号}/
  server/
    server.js
    public-mobile-h5/
  web/
    dist/
  miniprogram/              ← 微信开发者工具直接导入
  h5/                       ← H5 归档副本（与 server/public-mobile-h5 内容一致）
  android/                  ← 占位（空目录亦可）
  harmony/                  ← 占位（空目录亦可）
  修改记录.md
  生产部署说明.md           ← 可选，部署步骤速查，**必须放根下**
```

### B.2 部署映射表（用户直接复制）

| 升级包路径 | 服务器目标路径 | 说明 |
|---|---|---|
| `server/server.js` | `D:\wwwroot\jianyioa\server\server.js` | 后端主程序，覆盖后需重启 Node 服务 |
| `server/public-mobile-h5/` | `D:\wwwroot\jianyioa\server\public-mobile-h5\` | 移动端 H5 静态资源（后端托管 `/m/`） |
| `web/dist/` | `D:\wwwroot\jianyioa\web\dist\` | PC 前端（Vue3） |
| `miniprogram/` | 微信开发者工具导入目录 | 小程序源码，上传发版 |

> ⚠️ `server/public-mobile-h5/` 与 `h5/` 是**同一份 H5 构建产物**。前者是服务器实际托管目录，后者是归档副本。用户只需覆盖 `server/public-mobile-h5/` 即可。

### 红线 1：禁止创建任何额外包装目录

- **禁止**在 `v{版本号}/` 内创建 `生产升级包/`、`待上传/`、`发布包/`、`upgrade/`、`deploy/` 等任何中间包装目录。
- **禁止**出现 `v{版本号}/生产升级包/server/server.js` 这种双层嵌套。
- 原因：用户一直以来的操作是「打开版本号文件夹，直接复制里面的 server/、web/」，任何额外嵌套都会让用户困惑，导致发版结构「和之前不一样」。

### 红线 2：zip 打包规则

- **默认不打 zip**。用户直接复制文件夹即可，不需要压缩包。
- 若用户**主动要求**提供 zip，必须解决中文文件名跨平台乱码问题：
  - macOS 默认 `zip` 命令对中文目录名**不设置 UTF-8 标志位** → Windows 资源管理器解压后中文文件夹名变成乱码。
  - **正确做法**：用 Python 的 `zipfile` 打包（自动设置 UTF-8 标志位）。
  - **错误示范**：`zip -r v2.5.2.zip 生产升级包`（中文目录名 + 无 UTF-8 标志）。
- 若必须打 zip，优先让 zip 内不含中文目录名（用 ASCII 路径如 `upgrade/`），或明确告知用户用 `unzip` / Bandizip 解压，不要用 Windows 自带资源管理器。

### 红线 3：版本号一致性

- 五处 `package.json` 必须统一：根目录、`server/`、`web/`、`jianyioa-app/mobile/`、`jianyioa-mpweixin/mobile/`。
- **H5 界面版本号额外依赖 `manifest.json` 的 `versionName`**：
  - 只改 `package.json` 不改 `manifest.json` → H5 登录页/我的页仍显示旧版本号。
  - 正确流程：改 `package.json` → 同步改 `manifest.json`（versionName + versionCode）→ 重新 build H5 → 核验产物内版本号。
- 发版前核验命令：
  ```bash
  grep -rho "[0-9]\+\.[0-9]\+\.[0-9]\+" server/public-mobile-h5/ web/dist/ | sort -u
  ```

### 红线 4：数据库迁移已内置，升级包不附带额外脚本

- `server.js` 启动时会自动执行 `CREATE TABLE IF NOT EXISTS` 和幂等 `ALTER TABLE`（已覆盖 sms_codes、mall_orders、material_categories 等）。
- 升级包内的 `server/` **只需要 `server.js` + `public-mobile-h5/`**。
- **不要**把 `migrations/` 目录、`material-pinyin.js` 等辅助脚本塞进升级包。用户复制到服务器后，这些文件既不被引用又占地方。
- 若真有独立迁移脚本需要交给用户，应作为**单独文件**放在 `v{版本号}/` 根下（与 server/ 同级），并在 修改记录.md 中注明执行时机。

### 红线 5：构建产物必须重新生成

- 改完版本号后，**必须重新构建三端**（PC web、H5、小程序），不能只改 package.json 不 build。
- 产物复制必须使用 **覆盖/同步模式**（`rsync -a --delete` 或 `cp -R` 后清理旧 hash 文件），避免旧 chunk 残留导致 404。
- 小程序产物同步到 `jianyioa-miniprogram/` 时**必须原地覆盖**（`cp -R dist/build/mp-weixin/. ~/Desktop/jianyioa-miniprogram/`），禁止先 `mv` 再重建目录（会导致微信开发者工具索引失效）。

### B.3 总结口诀

> **版本号根下放标准目录，用户直接复制；不套包装、不打 zip、不带迁移脚本；改号必重建，产物必核验。**
