## 一、体检查了什么、怎么查

拆分的风险不是「服务起不来」——那种会立刻 503 被发现。真正的风险是**静默失效**：

| 风险类型 | 后果 | 本次检查方式 |
|---|---|---|
| 存根少传一个依赖 | 模块里解构出 `undefined`，只在调用到那条路时才炸 | `health-check.js` 解析每个存根的 deps 与模块解构做差集 |
| 模块存在但没接线 | 接口全 404，没人报错 | `check-server-deps.js` 孤儿检测 + `health-check.js` lib 孤儿检测 |
| 注册顺序变了 | 同方法同路径被后注册者覆盖 | 全量扫描重复注册 + 路由基线比对 |
| `const` 依赖在存根之后定义 | `ReferenceError: Cannot access before initialization`，启动即死 | `check-stub-order.py`（TDZ 守卫） |
| 头注释行数过时 | 后来人对着假信息改代码 | 解析注释声称行数 vs 实际行数 |
| 行为回归 | 接口返回结构/数据变了 | 冒烟 137 条 GET + 跨模块抽样 + 写路径实测 |

## 六、本次顺带修的两件事

### 6.1 `family-members` 三条写接口：身份改为服务端反查

**原状态**：从 `x-customer-id` 请求头和 `req.body.customer_id` 取客户 id。这两个值都是客户端可任意伪造的明文，而客户 id 是连续自增的——猜一串数字就能读走别人家的家庭成员（姓名 + 手机号），也能往别人家里塞成员。

**改法**：新增 `resolveOwnerCustomerId(req)`，一律由 `x-user-id` + `x-user-type` 经 `permCore.resolveCustomerIdentity` 反查：

- 主账户 → `customers.id`
- 副账户 → `family_members.customer_id`（其主账户的 `customers.id`）
- 员工 / 查不到 → `null`，调用方返回 401

**前端零改动**：H5 与小程序的 `App.vue` 都已包装 `uni.request`，自动注入这两个头（`family.vue` 用的是裸 `uni.request`，同样被包装覆盖）。

实测：

| 场景 | 结果 |
|---|---|
| 匿名 + 伪造 `x-customer-id: 5` | **401**（修复前 200，直接返回郭大大的姓名与手机号） |
| 员工刘天宇(id=13) + 伪造 `x-customer-id: 5` | **401** |
| 业主王二(id=13) + 伪造 `x-customer-id: 5` | 200，**空数组**（只认自己的身份，头部被忽略） |
| 郭大大(id=5) 正常访问 | 200，1 条 |
| 郭大大 不带 `x-customer-id` | 200，1 条（证明不依赖该头） |
| 匿名 DELETE / PUT / POST | **401** |
| 郭大大在 body 里谎报 `customer_id: 11` | 写入 `customer_id=5`（body 被忽略） |

测试数据已清理，`family_members` 恢复 7 行。

### 6.2 注释与死代码清理

- **27 个模块**的头注释「共 N 行」改为「搬入时 N 行」。因为加固与追加会让实际行数偏离，旧表述会误导后来人；「搬入时」永远正确。改后体检该项从 10 处告警 → 0。
- 删除 `server.js` 里的 `OLD_DISPATCH_APPROVE` 常量：一个用于「字符串补丁覆盖」的正则，从未被任何代码引用（该逻辑早已直接写在 `api/dispatches.js` 的 approve 路由里）。
- `scripts/route-inventory.js` 的鉴权特征表补入 `resolveOwnerCustomerId`，否则 `family-members` 会被误报成「未登录」。

## 七、发现但未处理的问题

### 7.1 `family-members` 的查询条件把 `customer_id` 和 `phone` 用混了（**功能本身是坏的**）

这不是安全问题，是既有 bug，且**改动属于行为变更，需要你确认后再动**。

当前实现：

```js
// GET：拿到主账户的 phone，再按 phone 查
members = await stmt.all(masterPhone);      // WHERE phone = ?

// DELETE / PUT：判断同家庭
const isSameFamily = masterPhone === member.phone;
```

而 `family_members.phone` 是**唯一键**（`uk_phone`）。于是：

- **GET 永远只返回主账户自己 1 条**。实测：客户 5 郭大大库里有 3 条（郭大大本人 / 郑大大·配偶 / 郑二·配偶），接口只返回 1 条。
- **DELETE / PUT 永远 403**：`masterPhone` 是主账户手机号，永远不等于其他成员的手机号；即便相等也会撞上「不能删除主账户」的 400。删改家庭成员这两个功能实际上从未生效过。

正确写法应该是按 `customer_id` 关联（库里客户 5 的 3 条记录 `customer_id` 都是 5）。修它会同时改变 GET 返回条数——前端 `family.vue` 本来就按多条渲染，改完反而正常，但这是行为变更，**未经确认我不动**。

### 7.2 `GET /api/contract-templates` 用 `SELECT *` 返回全字段（性能，非安全）

这个接口把 5 条模板的正文一起返回，合计约 **87.6 KB**（单条 `content` 13–21 KB）。本机跨公网连远程库，传输一次要 **1.7 秒**；只取 `id/name` 是 42 ms。

同一进程内对照（排除连接因素）：`SELECT 1` 55 ms、`system_logs` 30–48 ms、`contract_templates` 1900–3200 ms。**问题在返回体大小，不在网络也不在拆分。**

建议：列表接口不返回 `content`，编辑时再取单条。但要先确认前端模板列表是否用到正文预览，属于接口契约变更。

### 7.3 环境相关：本机连远程库导致响应波动

本机与线上连同一个远程库（`116.204.19.53:3306`），公网链路 RTT 波动大。`SELECT 1` 在 40–63 ms 之间跳动，大字段查询 1–7 秒。生产环境若为同机房/内网，不会有这个问题。

这也是 §5.2 那次超时的原因：冷启动后连接池尚未热，叠加 `contract_templates` 的 87.6 KB 返回体，单条超过 10 秒阈值；复跑即恢复。

### 7.4 天花板：`x-user-id` 仍可伪造

本次加固把门槛从「知道一个手机号 / 客户 id」提高到「知道一个 id 且该 id 绑定的手机号与你声称的一致」，**是实质提升但不是终点**。全系统没有 token / 签名校验，`x-user-id` 仍是明文头。真正的解是 `docs/鉴权加固方案-v2.5.0.md` 的 token 化会话。

### 7.5 冒烟覆盖缺口

冒烟只发 GET。**214 条写操作里，只有本次实测的 `contract-templates` 4 条、`family-members` 4 条有真实用例**。其余写路径（通知、导出、上传、审批）没有自动化回归，后续改动这些模块前需要手工验证。
