# 升级说明 · v2.4.0

> 发布日期：2026-10-21
> 上一版本：v2.3.11
> 版本性质：**大版本**（跨 v2.3.12 / v2.3.13 的改动合集 + 权限体系收敛 + PC 端与移动端能力对齐）

---

## 摘要

v2.4.0 只有一条主线：**让「权限配置」从"页面上勾了、实际不生效"变成"勾什么就生效什么"。**

围绕这条主线做了三件事：

1. **权限位补齐**——把散落在业务里的隐性判断（谁算管理、谁能看全部）统一成权限码，并让角色管理页能把它们全部授出去。
2. **PC 端追平移动端**——未读提醒、待办事项、借权登录、消息中心，这四项移动端早就有、PC 端一直没有。
3. **UI 语义化**——角色权限页从"27 行 × 7 列的数据库字段表"改成按业务分组的能力卡片，让非技术人员也能配权限。

**没有一个改动是为了升版本号而做的。** 全部来自实际使用中暴露的问题。

| 端 | 改动文件 | 增删行 |
|---|---|---|
| 服务端 | `server/server.js` | +261 / −87 |
| PC 端 | 17 个源文件（`web/src`） | +3867 / −512 |
| 移动端（H5 + 小程序） | 9 个源文件（`jianyioa-app/mobile/src`） | +528 含产物 |
| 文档 | `docs/升级说明-v2.4.0.md`（新增） | — |

## 一、PC 端新增能力

### 1. 未读提醒：侧边栏角标 + 顶部铃铛

移动端首页一直有铃铛红点，PC 端此前**完全没有提醒**——不进消息中心就不知道有新事项。

现在：

- 侧边栏「待办中心」「消息中心」两个菜单项带红色角标数字（超过 99 显示 `99+`）
- 顶部铃铛可点开，下拉显示最近 6 条未读消息，点击即标已读并跳到对应业务页
- 切换页面时刷新一次，另有 **60 秒轮询**兜底

涉及的计数接口：`/api/todo/center`（待办）、消息未读数接口。

### 2. 借权登录（impersonate）在 PC 端落地

admin 可以「以某员工身份」登录查看，逻辑与移动端完全一致：

- 借权期间当前用户**整体换成目标员工**，权限按目标员工算
- **admin 特权一并失去**——看到的才是对方真实视角，而不是"带着 admin 后门看"
- 刷新 / 重开浏览器后借权状态**仍然保留**（横幅还在）
- 顶部横幅可随时「退出借权」，恢复原管理员身份

相关文件：`web/src/stores/user.js`（+111）、`web/src/App.vue`。

### 3. 消息中心改造

- 新增**消息详情抽屉**（480px），不必跳出当前页
- 类型下拉只列业务常用几类，不再几十项糊满屏
- 点行 = 标已读 + 有对应业务页就直接跳，没有才开详情
- 后端 `/api/messages` 支持 `status` 筛选，并单独返回 `pending_count` 供角标使用

### 4. 待办中心（全新页面）+ 数据看板待办

PC 端此前没有「一个页面看全部待办」的地方，只能挨个模块翻。

新增 `/todo-center`：

- 按当前用户权限聚合六类待办：**采购审核 · 报销 · 合同 · 增减项 · 审批 · 派工**
- 顶部按分类筛选（带数量角标），点条目直达对应业务页
- 与移动端待办中心共用 `/api/todo/center`

数据看板同步嵌入该接口，只显示 `count > 0` 的分组，点条目直达业务页。

### 5. 客户列表整页重构（+745 行）

原来的分页是**摆设**（整份列表塞进表格，翻页不改变内容）。现在：

- 分页真实生效，筛选后总数变化时自动收敛页码，不会停在空白页
- 顶部概览统计（纯前端聚合，不额外打接口）
- 状态圆点胶囊、来源彩色 chip（按来源固定配色）、姓氏首字渐变头像
- 客户详情抽屉，可从详情直接跳编辑
- `tags` 字段归一化（库里是 JSON 字符串，之前直接 `Object.assign` 会让它变成字符串，后续 `push` 报错）

### 6. 角色权限页重构（+1572 行，本版本 UI 改动最大的一处）

**改前**：27 个模块 × 7 列（全部数据 / 读 / 写 / 删 / 重置密码 / 审核 / 财务）的灰格子大表。
30 多项权限平铺，配一个角色要横向扫 27 行，且"审核"和"财务"两列语义完全看不出来。

**改后**：

- **6 组能力卡片**：客户与合同 / 项目与执行 / 报价与预算 / 资金与票据 / 采购与物资 / 协同与系统
- **两类权限分色**：蓝色胶囊＝数据能力（查看/查看全部/编辑/删除）；琥珀色＝流程关卡（审批/财务受理）
- 采购卡片内嵌静态流程链：`提交申请 → 审批 → 财务受理 → 报销完成`，把"同一张单据的两道关"画出来
- 列名翻成人话：`全部数据`→查看全部、`读`→查看、`写`→编辑、`审核`→审批、`财务`→财务受理
- 模块名后 `ⓘ` 悬停出业务含义；胶囊悬停出"这个权限在业务里对应哪个按钮"
- 组头全选/清空；「只看已授权」过滤开关；顶部能力摘要（已开 N/M 项）
- **财务列收窄到只在采购管理出现**——因为后端只有 `purchase:finance` 真被校验，其余 5 个模块的 `xxx:finance` 是历史空壳
- **审批管理 / 报表管理** 加「仅菜单」角标：这两个模块的权限位后端未校验，勾选只控制菜单显隐

**同时修掉的一个隐患**：此前保存角色时，**界面表达不了的权限码会被静默丢弃**。
现在打开编辑时先快照 `originalPerms`，保存时先把快照里"界面上没有对应勾选框"的码原样带回去，再按勾选重建。7 个预置角色 round-trip 已验证无损。

### 7. 个人中心

- 模块卡片列表不再手写，改由 `utils/menu-config.js` 的 `buildPersonalSections()` 生成（此前两份手写菜单长期漂移，加一个模块要改两处）
- **修复「修改密码」点击无反应**：声明语句被一行 `//` 注释整句吞掉，`pwdDialogVisible` 从未声明
- **修复改密码必失败**：提交走裸 `axios`，不带 `x-user-id`，后端取不到人，永远返回「旧密码错误」

### 8. 项目详情

- 7 个页签按权限过滤，没权限的 tab 不再显示（此前只要进得了项目，所有 tab 都能点）
- 支持 `/projects?id=123` 深链直达，消息中心 / 待办中心可以直接跳进某个项目

### 9. 其他 PC 修复

| 问题 | 说明 |
|---|---|
| 发版后旧标签页报 MIME 错误 | 重建后 chunk hash 变了，旧页面懒加载旧 chunk 拿到 HTML。现 `router.onError` 识别后静默重载一次（30 秒节流防死循环） |
| 「业主端可见配置」整页读不到也存不了 | 请求路径写成 `/api/...` 而 axios 的 baseURL 已是 `/api`，实际请求 `/api/api/...` → 404；且响应拦截器已剥一层，页面又解构一次 `{ data }` → 永远拿到 undefined。**这个页面从上线起就没通过** |
| 「客户端可见配置」改名 | 统一为**「业主端可见配置」**——"客户端"是技术词，配置员容易和"业务端"混淆 |
| 采购申请角标数字偏大 | 只取「待上传回执」的 `pending_count` |

### 10. 三个新的前端基础模块

以前这类逻辑散在各页面里，改一处忘一处。本版本收进 `web/src/utils/`：

| 文件 | 作用 | 为什么必须统一 |
|---|---|---|
| `menu-config.js`（185 行） | **全站菜单唯一数据源**：侧边栏、个人中心卡片、路由权限都读它 | 此前侧边栏和个人中心各手写一份菜单，加一个模块要改两处，长期漂移 |

| `dicts.js`（39 行） | 状态/类型的统一字典与配色 | 同一个"待审核"在不同页面颜色不同 |

## 二、移动端 / 小程序（H5 与小程序**同源同改**）

> 注意：H5 分支 `mobile`、小程序分支 `mp-weixin`，两套源码必须同步修改，本版本已对齐。

### 1. 项目文件上传页

- **参数读取时机修正**：原来在 `setup()` 顶层调 `getCurrentPages()`，拿到的是**上一页**的 options，所以从项目详情进来时项目没绑定。改到 `onLoad(options)` 读取
- **项目锁定**：带 `projectId` 进来即锁定，卡片显示「已绑定」且不可再选（与其他模块口径一致）
- **中文乱码修复**：URL 参数按 `encodeURIComponent` 编码但未解码，补 `safeDecode()`
- **小程序端上传**：原来产物里残留 `new XMLHttpRequest`，小程序必崩。现按平台分流——H5 走 XHR + `FormData`，其余走 `uni.uploadFile` + `onProgressUpdate`
- 页面级 `project_file:write` 守卫；项目名以 `/api/projects` 返回为准，不再信任 URL 传参

### 2. 项目详情页权限过滤

原来 11 个 tab **硬编码渲染，完全没有权限判断**——只要进得了项目，派工、验收、合同、增减项全部可见可点。
现在改为 `TAB_DEFS` + `canSeeTab()` 驱动，没权限的 tab 不出现；若当前 tab 被隐藏，自动回落到第一个可见 tab。

> 技术坑记录：`watch(computed)` 写在外层会在 setup 阶段立即求值，若依赖的 ref 在后面才声明会直接抛
> `Cannot read properties of undefined (reading 'value')`。已改为在 `onMounted` 内注册。

### 3. 入口权限位改判（会影响老角色，见第四节）

| 入口 | 改前判定 | 改后判定 |
|---|---|---|
| 施工日志 | `project:write` | `project_log:write` |
| 主材管理 | `purchase:read` | `material:read` |
| 催收记录 | `finance:write` | `collection:write` |

改前这三处是**借用别的模块的权限位**来判定的，导致"给了项目经理项目写权限，他就顺带能进施工日志"。

### 4. 其他

- `utils/api.ts` 补齐（H5 端此前缺失，导致 `absUrl` / `absAsset` 找不到）
- `navigateBack:fail` 场景补 `safeBack()` 守卫（`switchTab` 会清空页面栈）

## 三、服务端

### 1. 财务收支：幂等 + 级联清理

这是本版本服务端最实质的修复。此前 `payment_records` 只有"插入"没有"撤销"，导致三类脏数据：

| 场景 | 改前 | 改后 |
|---|---|---|
| 合同审核通过 | 重复点会插多条收入记录 | 幂等保护，一份合同只产生一条 |
| 增减项审核通过 | 同上 | 幂等保护 |
| 派工审核通过 | 前端连点/重试会插多条 | 幂等保护 |
| 派工反审核 | 已产生的收支记录不撤销 | 一并撤销「待确认」收支 |
| 删除合同 / 增减项 / 派工 | 收支记录变孤儿，找不到来源单据 | 连带清理 |

另新增**催收记录确认入口**——此前 `payment_records` 只有插入、没有任何"确认"动作，钱到了账上系统里也没人能标记。

### 2. 权限口径修正

- **主材模块 `material` 正式生效**：`/api/materials` 的读写删与出入库改为 `material:*` **或** `warehouse:*` 任一命中即放行（迁移期两边都认）
- `purchase:view` 并入 `purchase:read_all`——`view` 在角色管理里没有对应勾选列，**永远授不出去**，等于死权限
- 新增 `checkAnyPermission(codes)` 工具函数，用于模块归属迁移期的兼容口径

### 3. 路由与静态资源

- **移动端 SPA 路径误判修复**：原来判定写的是 `startsWith('/m')`，把 PC 的 `/message-center`、`/main-materials`、`/material-orders` 全误判成移动端路径 → 直接访问或刷新这几个页面会加载移动端 H5。改为 `/m` 或 `/m/` 前缀
- **不存在的 `/assets/*.js` 返回 404**，不再回退 `index.html`。此前回退会让浏览器报 `'text/html' is not a valid JavaScript MIME type`，把"文件已不存在"这个真实原因完全掩盖

### 4. 消息「当前身份」解析修复

通知/消息的接收人判定此前混用了多个来源，已统一（详见 `server.js` 对应注释）。

## 四、升级后**必须人工做**的配置

> 这一节不是可选项。不做会有人"突然没有权限"。

### 1. 角色权限补勾

因为**入口权限位改判**（第二节第 3 条），老角色里靠"借位"生效的权限会失效：

| 角色 | 需要补勾 |
|---|---|
| 项目经理 | 施工日志（查看 + 编辑）、项目文件（全部数据 + 审批） |
| 设计师 | 施工日志（查看）— 若之前靠 `project:write` 顺带可见 |
| 工程监理 | 施工日志（编辑）— 若之前靠 `project:write` |

**做法**：角色管理 → 编辑角色 → 功能权限 → 对应卡片勾选 → 保存。

### 2. 确认「财务受理」列

财务列现在**只在采购管理出现**。如果过去给某个角色勾过合同/催收的「财务」，那是无效勾选（后端不校验），现在已隐藏，不影响功能。

### 3. 确认「只看已授权」默认关闭

新加的是纯展示过滤器，默认关闭，不会影响任何权限值。

### 5. 浏览器

前端 chunk 文件名全变。所有在线用户需要**硬刷新**（`Cmd/Ctrl + Shift + R`）一次。
本版本已加自动重载兜底：旧页面点开新路由会静默刷新一次拿新产物。

## 八、已知问题（本版本**未**修复，请知悉）

这些是审计中发现但**没有在这一版动**的问题。列出来是为了让它们不被遗忘，不是为了免责。

### 1. 密码明文存储（安全，优先级最高）

`employees.password` 存的是**明文**，后端用 `emp.password !== old_password` 直接字符串比对。

**影响**：任何能读到数据库的人（DBA、备份文件、SQL 注入）都能看到全部账号密码，而多数人会复用密码到别处。

**整改**：引入 bcrypt + 登录接口同步改造 + 存量密码迁移。属于独立任务。

### 2. 「审批管理」「报表管理」权限位后端零校验

`/api/approvals*` 没有任何 `checkPermission`，谁能审批由发起人在单据里填 `approvers_ids` 点名决定，**与角色权限无关**。
报表同理。

已在 UI 上加了「仅菜单」角标说明，配置员不会误以为勾了就生效。

### 3. 部分接口缺权限守卫

- `/api/rectification-issues`（整改单）
- `/api/project-gallery`（项目相册）

这两个是**真漏洞**：任何登录用户都能读写，没有模块级校验。

### 4. 三个模块只有 `read_all`、写删无独立校验

施工日志 `project_log`、报价 `quote`、催收 `collection`——数据范围受控，但"谁能改、谁能删"没有单独判定。

### 5. 空数据模块

`approvals`、`quotes`、`budgets`、`invoices`、`notices`、`material_orders` 六张表目前 **0 条数据**。
它们不是假功能（有接口、有页面），只是业务上还没用起来——但配置权限时容易误判"给了也没用"。
